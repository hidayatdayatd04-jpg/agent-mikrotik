# Prompt untuk AI coding

Salin paragraf di bawah ini ke AI coding yang mempunyai akses ke repo dan file plan lengkap.md. Dokumen rencana sudah mendeskripsikan referensi gambar agar tetap dapat digunakan jika gambar tidak ikut terbawa.

Kerjakan implementasi lengkap redesign dan penambahan fitur MikroTik Agent pada repo D:/agent-mikrotik dengan membaca seluruh file “plan lengkap.md” terlebih dahulu, lalu jadikan dokumen itu kontrak implementasi dan acceptance criteria. Ini aplikasi Bun + Hono API, React/Vite, SQLite/Drizzle, child MCP MikroTik, dan transaksi RouterOS Safe Mode; audit kode serta AGENTS.md bila tersedia, periksa git diff, dan pertahankan perubahan pengguna yang sudah ada. Ikuti gambar referensi melalui deskripsi visual di rencana: sidebar chat seperti ChatGPT yang dapat expanded/collapsed menjadi icon rail, avatar profil di bawah, canvas chat baru yang kosong dan lapang, menu titik tiga, serta baris proses expandable dengan panel terminal gelap. Pindahkan dropdown “Router percakapan” dari header ke menu (+) dalam field chat dan ubah namanya menjadi “Connector”; tambahkan ikon Plus/aksi “Tambah router” yang membuka Pengaturan → Connector Router dengan form tambah aktif, menyediakan jalan kembali ke chat dan mempertahankan draft, lampiran serta pilihan connector. Hilangkan pilihan “Tanpa router” dan “Tanpa router (dokumentasi saja)” dari UI, tetapi pertahankan connectionId null di backend sehingga pengguna tanpa router tetap bisa tanya jawab umum; permintaan akses router harus dijawab jujur ketika belum terhubung. Jangan diam-diam berpindah ke router lain karena fallback state, dan jangan menganggap hasil discovery atau Winbox sebagai bukti SSH aktif. Hapus badge “Mode: Read-Only” dan toggle Write dari header karena Write cukup dikelola melalui composer; pertahankan pemeriksaan status connected/identity, versi izin live dan pesan error server. Pusatkan seluruh halaman konfigurasi dalam shell Pengaturan dengan sidebar sendiri untuk Connector Router, Provider AI, Profil, Tampilan, Konteks/compact, Keamanan & Safe Mode, Arsip, Tentang dan Bantuan; reuse halaman/komponen bisnis yang sudah ada, hapus pintasan Connector Router dan Provider AI dari sidebar chat, serta hapus teks “Provider & Safe Mode” dan “Workspace lokal” dari sidebar tanpa menghapus data workspace. Sidebar chat hanya memerlukan chat baru, pencarian, daftar chat dan profil; sediakan tombol buka/tutup, persistensi preferensi tampilan, tooltip icon rail dan drawer mobile yang dapat dinavigasi keyboard. Klik profil membuka menu Profil, Pengaturan, Personalisasi, pilihan tema Terang/Gelap/Sistem, Bantuan dan Keluar; jangan menambahkan Upgrade plan atau menu fiktif dari screenshot. Buat login lokal dengan username persis “mikrotik-agent”, identitas alternatif yang diminta sebagai email persis “mikrotikagent”, serta password awal “mikrotik123”; perlakukan mikrotikagent sebagai alias login literal karena bukan format email umum, gunakan field Username atau email bertipe teks, dan izinkan login dengan kedua identitas tersebut. Implementasikan autentikasi backend nyata dengan password hash adaptif, session server dan cookie HttpOnly yang cocok untuk mode localhost/HTTPS, expiry, rate limit dan logout; jangan menyimpan token di localStorage atau membuat gate frontend saja. Seed akun secara idempotent, hubungkan ke workspace lama tanpa mengubah owner binding enkripsi dan tanpa reset password setiap restart, lindungi semua API data/SSE/export/terminal, pertahankan validasi Host/Origin dan localOnly, serta bersihkan stream/job/transaksi terkait saat session direvoke. Jangan tampilkan password default di halaman login dan jangan menambahkan OTP/SMTP/registrasi yang tidak diminta. Pada setiap item percakapan tambahkan menu titik tiga untuk Export Markdown .md, Rename, Hapus, Pin/Lepas pin dan Archive; sediakan restore dalam Pengaturan → Arsip, persistensikan metadata di DB, tampilkan tanggal dibuat dari createdAt serta kelompok recency yang jelas, dukung pencarian/pagination, dan gunakan aksi yang sama pada header. Export harus berisi seluruh transcript tersimpan, metadata aman, lampiran sebagai metadata, dan proses tersanitasi; jangan membatasi export pada 24 history model atau buffer SSE. Hapus hero “MikroTik AI Agent”, paragraf asisten marketing, semua kartu Monitoring/Status Interface & Traffic, Keamanan/Audit Keamanan & Firewall, Konfigurasi/Setup Hotspot & Limit Profil, Diagnostik/Ping & DNS, dan tulisan “Gunakan saran ini”. Tampilan chat baru hanya sapaan “Apa yang ingin Anda kerjakan?” dan composer tengah; jangan tampilkan header percakapan sampai pesan pertama terkirim, tetapi tombol buka sidebar tetap dapat diakses. Sesudah ada pesan, tampilkan header transparan dengan judul, Terminal, Export .md dan menu percakapan; jika memakai segmented Chat/Work seperti referensi, definisikan Work sebagai tampilan proses/terminal pada conversation yang sama, bukan mode izin baru. Implementasikan compact percakapan manual dan otomatis yang berjalan di backend dan terlihat dalam timeline, dengan otomatis default aktif, pengaturan ambang, progress/sukses/gagal nyata, summary versioning, source revision/throughSeq, satu job per conversation, CAS/idempotency, dan history asli tetap utuh untuk UI/export. Ganti pendekatan hanya mengambil 24 pesan terakhir menjadi context builder yang menghitung budget instruction, tool schema, lampiran, summary, recent turns, pesan baru dan output reserve; gunakan metadata model dan estimator berlabel jika token tidak diketahui tepat, lakukan compact sebelum context habis, periksa ulang saat model berubah dan setelah output tool besar, pertahankan pasangan tool call/result, serta gunakan summary sebagai data tidak tepercaya yang tidak dapat mengubah izin atau target live. Utamakan compact sebelum begin Safe Mode; compact di tengah run hanya pada batas turn lengkap dengan deadline/cancel, tidak boleh membuka transaksi baru, commit dini, atau mengulang tool mutasi. Tangani provider failure/overflow dengan retry terbatas sesuai rencana dan jangan menghapus transcript atau berpura-pura compact berhasil memakai mock. Tampilkan seluruh aktivitas tool yang benar-benar dapat diamati—baca/tulis, docs, penolakan policy, command, verifikasi, transaksi dan compact—sebagai timeline ringkas dengan chevron kanan yang membuka daftar/detail seperti referensi Ran commands; persistensikan event, korelasikan melalui activityId/toolCallId, dukung SSE reconnect dan pagination, tampilkan input/command/output yang tersanitasi, durasi, actor, status dan exit code hanya bila tersedia, serta jangan menampilkan kredensial, prompt rahasia atau reasoning internal. Bedakan komponen CodeBlock untuk contoh kode yang belum dieksekusi dari TerminalOutput untuk eksekusi aktual; berikan label bahasa, salin dan scroll, sanitasi HTML/ANSI/OSC, dan jangan menamai semua kode sebagai RouterOS. Tambahkan panel terminal RouterOS pengguna dari header dengan target connector, history command, draft multiline, streaming output, cancel, resize dan status autentik; bangun command runner RouterOS terkontrol lewat SSH backend yang dapat menegakkan klasifikasi risiko, bukan endpoint shell Windows/Bash atau raw PTY tanpa pengaman. Command baca hanya diizinkan jika terklasifikasi read, mutasi memerlukan Write dan transaksi Safe Mode yang benar, command unknown/script kompleks yang belum dapat divalidasi ditolak dengan alasan, lifecycle enable/commit/rollback tidak boleh diambil alih input command, dan jangan mengklaim semua operasi RouterOS dapat di-rollback. Buat adapter terminal RouterOS khusus AI dengan actor/channel terpisah tetapi execution service, PolicyDispatcher, kredensial backend, mode live dan TransactionCoordinator yang sama; setiap command AI muncul sebagai proses aktual di canvas, dan contoh PowerShell dalam gambar hanya acuan visual, bukan permintaan akses shell komputer host. Serialize pekerjaan user/AI pada router fisik yang sama termasuk connector alias, jangan mengambil alih sesi aktif, jangan replay command ketika reconnect/compact, dan tangani timeout, cancel, disconnect, Write OFF, logout serta restart dengan cleanup terverifikasi. Pertahankan perbaikan begin full-args, policy active hanya setelah begin sukses, fallback read-only dengan diagnosis, commit/rollback deterministik, event final transaksi sebelum run selesai, invalidasi katalog, forwarding read-only ke child dan reset Write/disconnect saat restart; jangan menyalin state machine atau membuat jalur bypass untuk terminal. Lakukan migrasi additive yang menjaga chat/provider/connector/lampiran lama, gunakan komponen dan dependency existing bila memadai, pisahkan shell, context service, activity repository, terminal adapter dan auth agar App.tsx tidak menjadi monolit. Kerjakan fase-fase di plan sampai end-to-end selesai, bukan hanya mock UI, lalu jalankan typecheck, tes API/packages, tes web, lint, build, dan E2E yang konfigurasinya memang tersedia; tambah regression test memakai kontrak produksi nyata untuk auth, data lama, chat management/export, compact, event recovery, command classification, transaksi dan konflik terminal user/AI. Bandingkan screenshot pada desktop/tablet/mobile serta light/dark dengan deskripsi referensi, pastikan keyboard/focus/reduced-motion baik, dan jangan klaim uji router/provider nyata bila hanya memakai transport simulasi. Laporkan file yang diubah per fitur, migrasi, hasil tes/build, bukti visual, cara menjalankan/login serta batas verifikasi. Jangan melakukan deployment, publikasi paket, reset DB/router, atau perubahan jaringan di luar kebutuhan implementasi yang diminta.
